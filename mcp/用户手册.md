# 下载系统 用户手册

> 这份是**给人看的**：所有下载（本机 + 各台 Windows PC）的统一入口在哪、怎么提交、怎么看进度、
> 怎么临时改线/插队。想改代码或看内部设计，看同目录 `README.md` 与
> `<工具目录>/README_download_worker.md`。

**一句话**：不管你手敲、这个 agent 还是别的 agent，下载申请都写进**同一个收件箱**，
由主驱动（driver）按**等级**排队派发；同一个 windows 口不会有两方同时抢。

---

## 1. 最快上手（三条命令）

```bash
cd <工具目录>

# ① 看现在在干什么（队列多长、几条线、哪个口在跑）
python3 dl_req.py list

# ② 提交一个下载（普通等级，默认）
python3 dl_req.py submit --item "item-001" --platform alpha \
    --outdir /abs/path/item-001 \
    --prefix <对象前缀> --build <构建名>

# ③ 看某个任务的进度 / 撤销还没被受理的申请
python3 dl_req.py show <申请id>
python3 dl_req.py cancel <申请id>
```

提交后**不需要等**：driver 每 ~5 秒排空一次收件箱，受理的进队列（在日志里打印排到第几位），
被拒的移进 `inbox/rejected/` 并写明原因（比如"盘上已经有了"）。
**driver 没在跑也不会丢**——申请留在收件箱里，等它启动。

在 agent 会话里则用 MCP 工具 `submit`（同一个东西，参数一样，见 §6）。
（`<工具目录>` = 工具脚本所在目录，下文同；MCP 里对应的环境变量是 `DL_WORKER_DIR`。）

## 2. 下载等级与排队规则

提交时可以指定等级（不指定 = **普通**）：

| 等级 | 数值 | 别名 | 什么时候用 |
|---|---|---|---|
| `p0` | 90 | urgent / 加急 | 用户当天要结果，必须立刻跑 |
| `p1` | 70 | high / 高 | 明确要优先于日常批量 |
| **`p2`** | **50** | normal / 普通 | **默认**，日常批量下载都走这档 |
| `p3` | 30 | low / 低 | 不急，先让别的跑 |
| `p4` | 10 | bulk / 批量 | 大批量囤数据、专门排在最后 |

**两条铁律**：

1. **等级高的先跑**；
2. **同等级内，后说（后提交）的先跑** —— 所以想插队可以①直接交更高等级，②同等级下晚点再说一次。

**本项目的口径**：批量主下载**一律普通（p2）**，
不给自己加急；插队只在明确要求时用。
driver 启动时装载的**老积压**也按普通档算：p0/p1 的新申请排在它前面，p3/p4 的排在它后面。

命令行里等级就写 `--level p1`（或 `--level 高`、`--level 70` 都认）；MCP 里写 `level: "p1"`。

## 3. 运行时控制（不用重启 driver）

```bash
python3 dl_ctl.py show                  # 先看：控制文件 + driver 实况
python3 dl_ctl.py lines 2               # windows 线数改成 2（默认会打断多余的在途下载并重排队）
python3 dl_ctl.py lines 2 --grace       # 同上，但让多余那条把手头的跑完再退
python3 dl_ctl.py pause / resume        # 暂停 / 恢复取新任务（在跑的不受影响）
python3 dl_ctl.py promote <名称子串>    # 提到队头（插队，最高档）
python3 dl_ctl.py drop <名称子串>       # 移出队列
python3 dl_ctl.py skip <子串> / unskip <子串> / unskip --all
python3 dl_ctl.py avoid <口> / unavoid <口>   # 让路：不再往这个口派（不打断在途）
python3 dl_ctl.py add --item N --platform alpha --prefix P --build B --outdir /abs/dir [--front]
```
<small>`add` 不加 `--front` = **普通等级 + 现在这个时刻**（等同"现在提交一份 p2"：排在那批老积压前面、
但仍排在 `promote`/`--front` 钉住的插队任务之后）；加了 `--front` 才是真正插到队头。</small>

退出码：`0` = 已生效；`3` = driver 读到了但还没确认（可能正忙，稍后 `show` 看 `rev_applied`）；
`4` = 没生效（参数错 / 没拿到锁）。
`win_lines` / `paused` / `skip` **存在控制文件里，重启后仍生效**。

## 4. 看状态（都只读，随时可跑）

```bash
python3 dl_req.py list                       # 排队中的申请（按实际派遣顺序，含"时:分"）
python3 dl_channels.py                       # **按通道（linux / <隧道口>）看每条线在下什么、到哪了、多快**
python3 worker_pool.py --json                # 各台 Windows PC 的口是否活着、当前流量
python3 dl_ctl.py lease show                 # 每个口谁在占（本 agent / 别的 agent / 未声明），我能分几条
python3 dl_ctl.py show                       # driver 实况（队列/线数/让路/上次应用的改动）
tail -f "<driver 日志>"                      # 主驱动日志（谁开始下、谁完成、谁被拒；路径见配置）
```

`dl_channels.py` 是**跨 agent** 的：别的 agent 直接钉某个口跑的线也照样列出来（owner 一栏写它自己的名字），
因为所有线都 spawn 同一个下载器进程，从 `/proc` 就能认出来。通道 = `linux`（服务器直连）
加上每个 Windows 出口一条，以**端口为代称**；空闲就写「空闲（无人使用）」。

在 agent 会话里对应 `queue_status` / `worker_status` / `lease_status` / `alerts` / `overview`；
其中 `queue_status` **现在也带这张按通道的进度表**（改动在下一次重启会话后生效；
没重启前用上面的 CLI 直接看，同一个脚本）。

**清单自管（`data_status.csv`）**——**系统自己管**，不用记着手工两步：

```bash
python3 inventory_refresh.py --status     # 只看状态（只读）：fresh / stale / scanning / pending_finish / stale_scan
python3 inventory_refresh.py              # = --auto：按状态自己决定（该扫就扫、扫完就收口）
```
driver **每 10 分钟**自己判一次（`[inventory]` 那行日志）；会话里对应 MCP 的 `inventory` 工具。
收口（`--finish`）会顺带重算 Notion 三张表，所以「每天至少同步一次」也一并满足了。

**台账（看"下过什么、到哪一步"）**：
一份 CSV（一行一物种）；位置不写死——用 `DL_STATUS_CSV` 指定，或放在配置文件里（见 §7），MCP 的 `overview` 工具读同一份
状态取值：`QUEUED` 排队中 / `DOWNLOADING` 在下（含中断残留） / `DONE` 已下完 /
`REPAIRING` 卡洞修复中 / `REPAIRED` 已修好 / `REPAIR_FAIL` 修不了。
**下载前可以先查它**：已经 `DONE` 的不用再下。

## 5. 临时单文件下载（不进队列）

偶尔就要一个文件（比如几百 MB 的单个大文件、校验清单），不值得排队的：

```bash
python3 linux_downloader.py "<URL>" -o "<输出路径>" --md5 "<官方md5>" --connections 4
```

它会自动挑一个**没被别人占**的 Windows 口（也可 `--worker http://127.0.0.1:<口>` 指定，默认并发 2、大文件可 `--connections 4`），后台断点续传；
中断了**重跑同一条命令**即续，别手动删输出文件。
MCP 里对应 `download` 工具（参数：`url` `output` `md5` `connections` `port` `direct`）。
小文件（<100 MB）直连不慢时也可以走老通道 `aria2c`。

## 6. 在 agent 会话里用（MCP 工具）

| 工具 | 干什么 | 必填参数 |
|---|---|---|
| `submit` | **提交下载申请**（进统一队列）；**一次投多条时给 `items`**（见下） | `name` `platform` `outdir`（+ 可选 `level` 等）；批量时只给 `items` |
| `queue_status` | 队列深度 / 在跑的线 / 口占用 / 控制状态 + **按通道（linux/<隧道口>）的逐线进度**（跨 agent）一屏 | — |
| `ctl` | 等于上面的 `dl_ctl.py`（`action`=lines/pause/resume/promote/drop/skip/unskip/avoid/unavoid） | `action` |
| `lease_status` | 每个口谁在占、我能分几条、有没有未声明的占用 | — |
| `worker_status` | 各台 PC 的口是否活着、延迟、流量 | — |
| `alerts` | 告警流水（下线 / 上线 / 争用 / 让路 / SSD 水位） | — |
| `overview` | 台账 CSV 汇总（按状态/物种筛） | — |
| `inventory` | **清单 `data_status.csv` 的自管刷新**（`action`=`status` 看状态 / `auto` 按状态自己决定 / `start` 起扫 / `finish` 收口并同步 Notion） | `action`（默认 `status`） |
| `download_status` | 单个输出文件的进度（读现有 sidecar） | `output` |
| `download` | **临时单文件**（不进队列，租约感知） | `url` `output` |

`submit` 的 `platform` 取 `alpha`（对象存储主通道）/ `beta`（对象存储副通道）/ `gamma`（http(s) 直链）；
`owner` 建议写自己的名字（默认 `agent`；多 agent 共用时各写各的，方便按归属查）。

**批量提交**（新增，**几百条一次投完，别一条一条调**）：给 `items` 数组，公共字段放 `defaults`：

```
submit(defaults={"platform":"gamma","outdir":"/abs/dir","owner":"agent","level":"p2"},
       items=[{"name":"item-001","url":"https://example.org/a.bin"},
              {"name":"item-002","url":"https://example.org/d.bin","level":"p1"}])
→ {"batch":true,"total":2,"submitted":2,"failed":0,"ids":[...]}
```

单次最多 **1000 条**；每条**独立校验**，某条缺字段只失败那一条（返回里 `errors` 写明第几条、什么原因），
其余照投；部分失败时 `isError=true`，但 `submitted`/`failed` 两个数分得清清楚楚。
命令行等价物：`python3 dl_req.py submit --batch-file list.json`（立刻可用，不受重启限制）。
新会话接入（注册片段）见同目录 `README.md`。

## 7. 东西都在哪

| 位置 | 是什么 |
|---|---|
| `mcp/mcp_server.py`（本仓库内） | **本 MCP 本体**（会话里的 `submit` 等工具） |
| `<工具目录>/` | **工具目录**：`dl_req.py` 申请、`dl_ctl.py` 控制、`dl_channels.py` **按通道看进度**、`dl_all_priority.py` 主驱动、`linux_downloader.py` 下载器、`worker_pool.py` 探活、`status_collector.py` 台账、`inventory_refresh.py` **清单自管**、`disk_trust.py` **盘上文件可信度判据**、`restart_driver_<driver>.sh` 重启 |
| 同上 `state/disk_trust_log.tsv` | **可信度判定台账**：谁（driver/下载器/agent）在什么时候判了哪个文件、判成什么（trusted/bad/unknown）、依据的大小（本地 vs 远端）——「为什么这个文件被判已下过」查这里 |
| 同上 `inbox/`（+`done/` `rejected/`） | 收件箱：申请单、已受理、被拒（带原因） |
| 同上 `control/<driver>.json` | 运行时控制（线数/暂停/跳过/让路） |
| 同上 `state/` | driver 快照、broker 账本、pid 等；`driver_<driver>.ranks.json` = 队列的**等级表**（每 15s 随快照落盘，重启后照它恢复排队顺序）；`driver_<driver>.queue.json` = **队列快照**（待跑+在途，同上频率；重启后据此恢复） |
| 同上 `lease/` | 口租约（谁在占哪个口） |
| `~/.config/download-worker/dw_tasks.json` | **本机路径配置**（台账、告警、别的 driver 台账的位置都在这；`DW_TASKS_CONFIG` 可换位置）—— 公开仓库里不写死本机目录，所以这些位置由它给 |
| 下载台账 CSV | 进度对照表；路径由 `DL_STATUS_CSV` 或配置文件的 `status_csv_candidates` 指定（同 `linux/dw_tasks.py`） |
| 告警流水 JSONL | 路径由 `DL_ALERTS_FILE` 或配置文件的 `alerts_file` 指定 |
| driver 自己的运行日志 | 主驱动日志（路径见配置的 `drivers.*.log`） |
| tmux 会话 `<driver>` | 主驱动在跑的地方（另见 `dlbroker_<driver>`、`statusbroker_<driver>` 等守护） |
| Windows PC | `127.0.0.1:<口>`（**每台一个口**，装的时候定）；**只走 127.0.0.1，不直连 PC 的 IP** |

## 8. 常见问题

**Q：提交后一直没动？**
先 `dl_req.py list` 看申请还在不在收件箱；在的话看 driver 有没有在跑（`dl_ctl.py show`）。
被拒的会带原因（最常见的：盘上已经下过、队列里已有同一物种同一平台）。

**Q：被拒了说"盘上已有落地文件"——它怎么知道我下过了？**
**拒绝一律带证据**（「先验再拒」）：系统会去问远端**这个文件到底多大**，
跟盘上那份逐字节比大小——一致才判 `trusted` 并拒；**不一致（`bad`）不拒、直接重新下**；
问不到远端（网络问题）算 `unknown`，**也不拒**（宁可不拒也不误拒），但会记一条告警。
每次判定都留在 `state/disk_trust_log.tsv`，可以事后核对。判据代码是 `disk_trust.py`（driver 与下载器共用同一套）。

**Q：清单（`data_status.csv`）多久刷一次？**
系统自己管：CSV 超过 24h 就起一轮扫描、扫完自动收口并同步 Notion；driver 每 10 分钟判一次。
手动看/推：`python3 inventory_refresh.py --status` / MCP 的 `inventory` 工具。

**Q：重启 driver 会不会把排队中的任务弄丢？**
**不会**：队列（待跑 + 正在下的）每 15 s 落一份 `state/driver_<name>.queue.json`，
启动时自动读回并去重合并（此前的版本会丢）。实测两次重启队列零丢失
（日志会打 `[queue] 队列恢复：快照 N 条 → 补回 M 条`）。
**注意**：正在下到一半的那几个文件会从头重排队（sidecar 在，续传即回，最坏损失 1 个块）。

**Q：两个 agent 会不会抢同一个 windows 口？**
不会。所有申请走同一个队列，口用"租约"记名（`dl_ctl.py lease show` 能看到谁在占）；
driver 只往空口派活。真出现别人没走队列直接占用，会在告警流水里记为 `oversubscribed`，
系统会让路并告警，不会去抢。

**Q：想立刻下某个东西怎么办？**
`python3 dl_req.py submit ... --level p0`（加急，排到最前）；或者已经排队了就用
`python3 dl_ctl.py promote <物种名>`。

**Q：能加几条线？**
默认最多 8 条（`WIN_LINES_MAX`），日常 2–3 条就够。`dl_ctl.py lines N` 随时改。
线越多每条越慢（PC 上行是共享的），所以不是越多越好。

**Q：SSD 中转会不会满？**
下载中转目录有配额上限，超了会告警并自动降速；**只报不删**，
不会去删别的 agent 名下的文件。

**Q：下完的文件怎么算"真的完整"？**
每个文件落地都要过"大小 + 官方 md5 + 卡洞扫描（zero_scan）"三关，全绿才标 `DONE`；
落地后还会做一次流式完整性检查。中途卡洞（字节数对、中段是 0）会进 `REPAIRING` 流程修复。

**Q：怎么重启 driver？**
```bash
bash <工具目录>/restart_driver_<driver>.sh --check   # 先看现状
bash <工具目录>/restart_driver_<driver>.sh           # 重启（正在回读校验时会拒绝）
```
别手工 `python3 dl_all_priority.py`（会起出第二个 driver，有单实例守卫会挡）。
